Data Designer configurations are mostly portable between direct library usage and NeMo Platform plugin execution. The main migration question is which resources the configuration references.

See [Execution Modes](/documentation/design-synthetic-data/execution-modes) for the full two-axis model.

## What Usually Stays the Same

Most configuration code can stay unchanged:

| Configuration area | Portability |
|--------------------|-------------|
| Column definitions | Same across direct library usage, CLI `submit`, and SDK execution. |
| Prompt templates and Jinja2 references | Same across execution modes. |
| Constraints and profilers | Same across execution modes. |
| Model aliases and inference parameters | Same across execution modes. |
| Processors and generated dataset schema | Same across execution modes, subject to features supported by NeMo Services. |

For CLI execution, put your configuration in a Python module that exposes `load_config_builder()`. The plugin CLI loads the builder and submits it to NeMo Services.

## Moving to NeMo Platform Execution

Use NeMo Platform execution when you want service-managed workload execution, logs, jobs, and artifacts. When moving a direct-library configuration to CLI `submit` or SDK execution, check these areas:

| Area | Direct library usage | NeMo Platform `submit` / SDK | Migration action |
|------|----------------------|------------------------------|------------------|
| **Inference** | Local providers. | Inference Gateway providers. | Register an Inference Gateway provider and reference it by workspace/name, such as `default/nvidia-build`. |
| **Secrets** | Environment variables or plaintext values. | Secrets API secrets. | Create Secrets API secrets and reference them from the configuration. |
| **Seed data** | Local files, DataFrames, HuggingFace, or Filesets. | HuggingFace or Filesets. | Upload local seed data to a Files API Fileset or use HuggingFace. |
| **Personas** | Local persona datasets downloaded to the managed assets directory. | Persona Filesets in NeMo Services. | Use `nemo data-designer personas make-fileset` for required locales. |
| **Artifacts** | Local filesystem output. | Job artifact storage. | Use job status/logs and artifact download helpers. |

## Migration Checklist

Before moving a configuration into NeMo Platform, verify:

- The configuration source exposes `load_config_builder()` for CLI execution.
- Model providers referenced in `ModelConfig.provider` exist in Inference Gateway.
- Secret references resolve through the Secrets API.
- Seed data sources are compatible with service-backed execution.
- Persona datasets are published as Files API Filesets as needed.

This guide shows how to load agent traces into NeMo Platform, run the Analyst to
find an issue, and launch the Experimentalist to repair it. It uses smoke-agent:
a small, predictable example with known failures. The guide starts with one
failure, then shows how to try the same workflow with a broader set of failures.

To optimize an agent you already have, follow the [agent onboarding guide](/documentation/get-started) instead.
For component details, see the [Insights Analyst](https://github.com/NVIDIA-NeMo/nemo-platform/blob/main/plugins/nemo-insights/README.md),
[Eval Author](https://github.com/NVIDIA-NeMo/nemo-platform/blob/main/plugins/nemo-eval-author/README.md),
and [Experimentalist](https://github.com/NVIDIA-NeMo/nemo-platform/blob/main/plugins/nemo-experimentalist/README.md)
READMEs.

## Prerequisites

- Git, GNU Make, uv, and pnpm
- Docker Engine 29.6.2 or later
- [Docker Sandboxes](https://docs.docker.com/ai/sandboxes/) (`sbx`) 0.37.1 or later
- A default and fast Model Entity configured in NeMo Platform

## 1. Clone and bootstrap NeMo Platform

```bash
git clone https://github.com/NVIDIA-NeMo/nemo-platform.git
cd nemo-platform
make bootstrap
```

## 2. Start NeMo Platform

This step installs the Platform and helps you connect the models it will use.
Make sure Docker Desktop or the Docker daemon is running, then start setup:

```bash
uv run nemo setup
```

Agent traces are stored in ClickHouse. Intake automatically provisions a local
container; to use an external instance, set `NMP_INTAKE_CLICKHOUSE_URL` before
running setup.

Register the provider you want Platform agents to use, then select a default
model and a fast model. Press Enter at the fast-model prompt to reuse the
default model. `nemo setup` stores credentials in Platform Secrets and creates
workspace-qualified Model Entities. Confirm that the Platform is ready:

```bash
export NMP_BASE_URL=http://localhost:8080
curl -sf "$NMP_BASE_URL/health/ready"
```

Open [NeMo Studio](http://localhost:8080) to browse the workspace, traces, and
optimization runs created below.

## 3. Prepare smoke-agent

The smoke agent makes no model calls. It reads a small records file with regular
expressions, so its baseline failure is repeatable. The Analyst and
Experimentalist do use the Model Entities configured above.

The first problem is simple: the agent can look up, list, and count records,
but cannot calculate total hours. Its validation tasks vary the scope from a
department to all records or a role, so a narrow repair does not transfer. Later
sections combine this problem with other weaknesses, including long inputs,
dispatch order, and edge cases.

Run model-authored work in a Docker Sandbox. Clone mode gives the sandbox a
private writable checkout, so generated code cannot modify your working tree.

```bash
repo="$(git rev-parse --show-toplevel)"
smoke="plugins/nemo-experimentalist/examples/smoke-agent"
platform_url="http://host.docker.internal:8080"
workspace="canonical-smoke-agent"
no_proxy="localhost,127.0.0.1,::1,gateway.docker.internal,host.docker.internal"
sandbox_env=(
  --env UV_PROJECT_ENVIRONMENT=/home/agent/.venvs/nemo-platform
  --env OTLP_ENDPOINT=http://host.docker.internal:5001/v1/traces
  --env NO_PROXY="$no_proxy" --env no_proxy="$no_proxy"
)

uv run --frozen nemo workspaces create "$workspace" \
  --description "Smoke-agent Experimentalist runs" \
  --exist-ok

sbx create --clone --name nemo-experimentalist shell "$repo"
sbx exec --user root nemo-experimentalist bash -lc \
  'apt-get update && apt-get install -y --no-install-recommends build-essential python3-dev'
sbx exec --workdir "$repo" nemo-experimentalist bash -lc \
  "cd $smoke && uv run --no-project scripts/build_image.py"
```

<Warning>
Clone mode protects the host checkout from writes, but it does not isolate
credentials or host services from code in the sandbox. Use dedicated,
revocable credentials and expose only the model access this example needs.
</Warning>

## 4. Run the Analyst

Now that the Platform is running, record traces that show the example agent
failing to calculate total hours.

```bash
sbx exec --workdir "$repo" "${sandbox_env[@]}" \
  nemo-experimentalist \
  bash -lc "uv run --frozen --python 3.13 \
    --package nemo-experimentalist-plugin --with ./plugins/nemo-agents \
    python $smoke/scripts/record_traces.py \
      --group g1-aggregation \
      --split insight-evidence \
      --workspace $workspace \
      --agent $smoke/agent \
      --dataset-root $smoke/dataset \
      --output /tmp/smoke-g1-recordings \
      --base-url $platform_url"
```

If a trace cannot be retrieved, do not continue; rerun the recording command
after checking that the Platform is ready.

The uploaded traces appear in the [Traces view](http://localhost:8080/studio/workspaces/canonical-smoke-agent/intake/traces).

The Analyst reads those traces and files an Insight in the Platform. An Insight
is a human-readable description of a recurring problem, similar to a bug report.
It includes the trace IDs that support it; it does not prescribe a code change.
The Experimentalist diagnoses and repairs the implementation from that evidence.

```bash
sbx exec --workdir "$repo" "${sandbox_env[@]}" \
  nemo-experimentalist \
  bash -lc "uv run --frozen --python 3.13 \
    --package nemo-experimentalist-plugin --with ./plugins/nemo-agents \
    nemo agents analyst run \
      --agent smoke-agent \
      --agent-spec $smoke/AGENT-SPEC.md \
      --workspace $workspace \
      --base-url $platform_url"
```

The Analyst prints whether it created or updated an Insight. Open the
[Insights view](http://localhost:8080/studio/workspaces/canonical-smoke-agent/optimizer),
select the total-hours Insight, and copy its platform ID. Check that it has a
clear title, an actionable description, and non-empty trace references before
continuing.

```bash
insight_id="<the Platform Insight ID>"
```

## 5. Optimize performance with the Experimentalist

The Experimentalist runs the evaluations, diagnoses the failure from the trace
data, proposes a code change, and validates it against new tasks and regression
checks.

The default G1 scenario typically takes tens of minutes; allow up to an hour.

The Experimentalist generates a draft pull request (PR) or merge request (MR)
when it receives a GitHub or GitLab agent source. It creates a branch only when
a changed candidate wins validation.

Git integration is optional. To run the optimization without creating a
repository or PR/MR, [jump to the local-only alternative](#optional-run-locally-without-creating-a-pr-or-mr).
A local Git repository is also sufficient when it is reachable from the sandbox;
a remote is only needed to publish a PR or MR.

To optimize the example agent, create a private GitHub repository with the
[GitHub CLI](https://cli.github.com/) and populate it with the smoke-agent
source. Replace `your-github-user-or-org` with the GitHub account or
organization that will own the repository.

```bash
gh auth login
# Choose HTTPS when prompted for the preferred Git protocol.
export GITHUB_OWNER="your-github-user-or-org"
mkdir -p "$HOME/src"
cd "$HOME/src"
gh repo create "$GITHUB_OWNER/smoke-agent" --private --clone
export EXAMPLE_AGENT_REPO="$PWD/smoke-agent"
cd -
rsync -a --exclude='.env' --exclude='.env.*' "$smoke/agent/" "$EXAMPLE_AGENT_REPO/"
rsync -a --exclude='.env' --exclude='.env.*' "$smoke/AGENT-SPEC.md" "$EXAMPLE_AGENT_REPO/"
git -C "$EXAMPLE_AGENT_REPO" checkout -b main
git -C "$EXAMPLE_AGENT_REPO" add .
git -C "$EXAMPLE_AGENT_REPO" commit -m "Add the smoke-agent example source"
git -C "$EXAMPLE_AGENT_REPO" push -u origin main
export AGENT_REPO_URL="https://github.com/$GITHUB_OWNER/smoke-agent.git"
```

Run the Experimentalist against the Git repository inside a Docker Sandbox. It
clones the agent, validates an improvement, pushes the winning version to a new
branch, and opens a draft PR or MR against `main`. Authenticate GitHub inside
the sandbox so it can clone and push the private repository.

```bash
sbx create --clone --name nemo-experimentalist-git shell "$repo"
sbx exec --user root nemo-experimentalist-git bash -lc \
  'apt-get update && apt-get install -y --no-install-recommends build-essential python3-dev'
gh auth token | sbx exec -i --workdir "$repo" nemo-experimentalist-git \
  gh auth login --with-token
sbx exec --workdir "$repo" nemo-experimentalist-git gh auth setup-git
sbx exec --workdir "$repo" nemo-experimentalist-git bash -lc \
  "cd $smoke && uv run --no-project scripts/build_image.py"

sbx exec --workdir "$repo" "${sandbox_env[@]}" \
  nemo-experimentalist-git \
  bash -lc "uv run --frozen --python 3.13 \
    --package nemo-experimentalist-plugin --with ./plugins/nemo-agents \
    nemo agents experimentalist run \
      --profile $smoke/optimizer.yaml \
      --agent ${AGENT_REPO_URL}@main \
      --agent-spec $smoke/AGENT-SPEC.md \
      --insight $insight_id \
      --workspace $workspace \
      --base-url $platform_url \
      --config $smoke/configs/short.yaml \
      --experiment-dir /tmp/smoke-g1-insight-git"
```

After the run, inspect the draft PR or MR that the Experimentalist opened for
the winner. GitLab is supported too: use a GitLab repository URL and
authenticate with `glab auth login` in the sandbox. By default the
Experimentalist publishes only the winning candidate. Set
`storage.archive_candidates: true` in a separate run configuration when you
also need every generated candidate branch for review.

### Download and inspect the experiment

Copy the complete experiment directory to the host after the run finishes. It
contains the resolved baseline, generated candidates, per-task results, logs,
and the run summary:

```bash
experiment_dir="/tmp/smoke-g1-insight-git"
download_dir="tmp/smoke-agent-artifacts"
mkdir -p "$download_dir"
sbx cp "nemo-experimentalist-git:$experiment_dir" "$download_dir/"

artifact_dir="$download_dir/smoke-g1-insight-git/eval-and-optimize"
sed -n '1,240p' "$artifact_dir/run.json"
find "$artifact_dir/results" -name 'metric_*.json' -print
diff -ru "$artifact_dir/agents/agent-0" "$artifact_dir/agents/agent-1"
```

The `diff` command exits with status 1 when it finds candidate changes, which
is expected. The trace records include the Experimentalist evaluation ID and
smoke-agent task ID.

### Optional: run locally without creating a PR or MR

Use this alternative if you do not want to create or push to a repository. It
changes only a private sandbox clone and never creates a PR/MR. The sandbox uses
`host.docker.internal` to reach Platform services on the host:

```bash
sbx exec --workdir "$repo" "${sandbox_env[@]}" \
  nemo-experimentalist \
  bash -lc "uv run --frozen --python 3.13 \
    --package nemo-experimentalist-plugin --with ./plugins/nemo-agents \
    nemo agents experimentalist run \
      --profile $smoke/optimizer.yaml \
      --insight $insight_id \
      --workspace $workspace \
      --base-url $platform_url \
      --config $smoke/configs/short.yaml \
      --experiment-dir /tmp/smoke-g1-insight-local"
```

The sandbox needs access to the package, model, Docker daemon, and Platform
endpoints used by the run. `host.docker.internal` reaches the Platform service
on the host; the safety boundary described above applies here too.

After the run completes, inspect the run summary and compare the baseline with
the candidate. The `diff` command exits with status 1 when it finds candidate
changes, which is expected:

```bash
artifact_dir="/tmp/smoke-g1-insight-local/eval-and-optimize"
sbx exec --workdir "$repo" nemo-experimentalist \
  sed -n '1,240p' "$artifact_dir/run.json"
sbx exec --workdir "$repo" nemo-experimentalist \
  diff -ru "$artifact_dir/agents/agent-0" "$artifact_dir/agents/agent-1"
```

Copy artifacts you want to retain to the host before removing the sandbox:

```bash
mkdir -p tmp/smoke-agent-artifacts
sbx cp "nemo-experimentalist:$artifact_dir" tmp/smoke-agent-artifacts/
```

## Optional: run directly from datasets

Mode 2 skips the Analyst and Insight. Use it when you already have a trusted
train and validation dataset and want to optimize directly against it. This
uses the same `g1-aggregation` repair scenario, but passes `--no-insight`.

```bash
sbx exec --workdir "$repo" "${sandbox_env[@]}" \
  nemo-experimentalist \
  bash -lc "uv run --frozen --python 3.13 \
    --package nemo-experimentalist-plugin --with ./plugins/nemo-agents \
    nemo agents experimentalist run \
      --profile $smoke/optimizer.yaml \
      --no-insight \
      --base-url $platform_url \
      --config $smoke/configs/short.yaml \
      --experiment-dir /tmp/smoke-g1-datasets"
```

## Optional: run the combined scenario

The combined scenario joins the supported repair groups, runs up to five rounds,
and exercises survivor selection, candidate ranking, and convergence. It can
take one to two hours.

Build the generated dataset, then use its profile with `full.yaml`:

```bash
sbx exec --workdir "$repo" nemo-experimentalist bash -lc \
  "cd $smoke && uv run --no-project scripts/build_all_group.py"

sbx exec --workdir "$repo" "${sandbox_env[@]}" \
  nemo-experimentalist \
  bash -lc "uv run --frozen --python 3.13 \
    --package nemo-experimentalist-plugin --with ./plugins/nemo-agents \
    nemo agents experimentalist run \
      --profile $smoke/optimizer-full.yaml \
      --no-insight \
      --base-url $platform_url \
      --config $smoke/configs/full.yaml \
      --experiment-dir /tmp/smoke-all"
```

The combined dataset is generated and not committed. Rebuild it after changing
an included group. The [smoke-agent README](https://github.com/NVIDIA-NeMo/nemo-platform/blob/main/plugins/nemo-experimentalist/examples/smoke-agent/README.md)
lists the included groups and explains why others are held out.

`OTLP_ENDPOINT` routes sandbox telemetry to the host trace collector. The
`host.docker.internal` address is required because the sandbox has its own network namespace.

## Clean up

Stopping preserves each sandbox's private checkout, experiment output, installed
packages, and image cache. Remove both sandboxes when that state is no longer useful:

```bash
for sandbox in nemo-experimentalist nemo-experimentalist-git; do
  sbx stop "$sandbox"
  sbx rm "$sandbox"
done
```

This page is the reference for **what kinds of telemetry Intake stores and what values each kind carries**. Each top-level object can be rendered with a distinct view: an LLM span looks different from a tool span, an evaluator result looks different from an annotation, and so on.

Everything here is derived from the source of truth in the Intake service:

- `services/intake/src/nmp/intake/spans/domain.py` — domain models (enums, `IntakeSpan`, `IntakeTrace`, `EvaluatorResult`, `Annotation`).
- `services/intake/src/nmp/intake/spans/span_attribute_catalog.py` — which semantic attributes exist, which source keys feed them, and where they are stored.
- `services/intake/src/nmp/intake/spans/api/spans_schemas.py` — the **read** shape (`Span`) the API/SDK/frontend actually receives.
- `services/intake/src/nmp/intake/spans/api/traces_schemas.py` — the read shape for `Trace`.
- `services/intake/src/nmp/intake/spans/api/evaluator_results_schemas.py` — `EvaluatorResult` read/write.
- `services/intake/src/nmp/intake/spans/api/annotations_schemas.py` — kind-discriminated `Annotation` read/write.

The four top-level objects a view can encounter:

1. **Trace** — a roll-up over a tree of spans for one session/run.
2. **Span** — a single unit of work; its `kind` selects the per-type template.
3. **EvaluatorResult** — an automated score attached to a span/session (separate table).
4. **Annotation** — a post-hoc human/process signal on a span/session (separate table).

## Trace

A `Trace` (`traces_schemas.Trace`) is a computed summary over the spans that share a canonical trace id. The frontend uses it for the traces list and the trace header.

| Field | Type | Notes |
|---|---|---|
| `id` | string | Canonical Intake trace id. |
| `root_span_id` | string \| null | Span id of the root span, when one is found. |
| `session_id` | string | Correlation key (from `gen_ai.conversation.id` / `session.id`, else derived). |
| `workspace` | string | |
| `name` | string \| null | Root span name. |
| `experiment_context` | `{experiment_id, test_case_id}` \| null | Present only when the root span carries `nemo.experiment.id`. Drives the Experiments surfaces. |
| `started_at` / `ended_at` | datetime \| null | |
| `duration_ms` | float \| null | |
| `status` | `SpanStatus` | Root span status (see below). |
| `input_tokens` / `output_tokens` / `cached_tokens` / `total_tokens` | int \| null | Summed across spans. |
| `cost_usd` / `cost_input_usd` / `cost_output_usd` | float \| null | Summed across spans. |
| `span_count` | int \| null | |
| `error_count` | int \| null | Number of error spans; drives "N errors" badges. |

A trace view should handle: no name, no experiment context, null token/cost roll-ups (e.g. a trace made only of tool spans), and `error_count > 0`.

## Span

A `Span` (`spans_schemas.Span`) is the central object. **`kind` is the discriminator** the per-type template keys off. Every span — regardless of kind — carries the same flat field set; what differs is *which fields are populated* and what lands in the `raw_attributes` bucket.

### Span kinds (`SpanKind`)

```
LLM  CHAIN  TOOL  RETRIEVER  EMBEDDING  AGENT  RERANKER  EVALUATOR  GUARDRAIL  UNKNOWN
```

The kind comes from the OpenInference `openinference.span.kind` attribute (uppercased); anything unrecognized becomes `UNKNOWN`.

### Span status (`SpanStatus`)

```
success  error  cancelled  unknown
```

### Per-kind expectations (what a view should render)

> "Populated" = realistically present; everything else falls through to `raw_attributes`.

- **LLM** — `provider`, `model`, token counts (`input/output/cached/total`), optional `usage_details`, `cost_*`, optional `prompt_id`. `input`/`output` are JSON message arrays (`{"messages":[{role,content,tool_calls?}]}`). Sampling params like `temperature`/`top_p`/`max_tokens` are **not** semantic fields → they live in `raw_attributes`.
- **TOOL** — `tool_name`, `input` (tool arguments JSON), `output` (tool result). No LLM meta, no tokens, no cost. Anything tool-specific (e.g. `tool.parameters`) → `raw_attributes`.
- **RETRIEVER** — `input` is the query. Retrieved docs (`retrieval.documents.*`) are not promoted → they land in `raw_attributes`. Usually no tokens/cost.
- **EMBEDDING** — `model`, `provider`, often `input_tokens`/`total_tokens` and `cost_*`. Embedding vectors / text (`embedding.embeddings.*`) → `raw_attributes`.
- **RERANKER** — `model` optional. Query + candidate documents and scores → `raw_attributes`.
- **AGENT** — `agent_name`, `agent_id`, `agent_version` (version is in `raw_attributes` — it's not on the read model). `input`/`output` are the task and final result. Usually a parent in the hierarchy.
- **CHAIN** — orchestration/composite. Often just `name`, `input`, `output`; a structural parent with little semantic metadata.
- **EVALUATOR** — an evaluation step expressed as a *span*. May or may not carry LLM meta (LLM-as-judge has `model`/`provider`; a deterministic/code check does not). The score itself is typically recorded as a separate **EvaluatorResult** row (see below), joined by `session_id`/`span_id`. Score, rationale, threshold etc. that are on the span land in `raw_attributes`.
- **GUARDRAIL** — content-safety / jailbreak / PII rail. Decision (`blocked`, category, confidence) → `raw_attributes`; `status=error` when a rail trips. May carry `model`/`provider` for an LLM-based rail.
- **UNKNOWN** — fallback for any span whose `openinference.span.kind` wasn't recognized. A view should degrade gracefully to name + input/output + raw attributes.

## EvaluatorResult

`EvaluatorResult` (`evaluator_results_schemas.EvaluatorResult`) is an **automated** score, stored in its own table and joined to a span/session by id (loose target — the `span_id` is not validated against the spans table). An evaluator result always carries a score plus identifying information.

| Field | Type | Notes |
|---|---|---|
| `evaluator_result_id` | string | Server-set. |
| `span_id` | string | Target span (loose). |
| `session_id` | string | Denormalized target session. |
| `workspace` | string | |
| `name` | string | Evaluator/metric identity, e.g. `faithfulness/v1`, `pass`, `toxicity`. |
| `value` | float \| null | Required for `NUMERIC` and `BOOLEAN` (0\|1). |
| `string_value` | string \| null | Required for `CATEGORICAL` and `TEXT`. |
| `data_type` | `EvaluatorResultDataType` | Discriminator. |
| `comment` | string \| null | Free-text rationale (e.g. LLM-judge explanation). |
| `created_by` | string \| null | Principal/system that wrote it. |
| `created_at` / `ingested_at` | datetime | |

### Data types (`EvaluatorResultDataType`)

```
NUMERIC  CATEGORICAL  BOOLEAN  TEXT
```

The same evaluator concept spans very different shapes — a view must handle all four:

- **NUMERIC** — `value` ∈ ℝ (typically [0,1] or a rubric score). LLM-as-judge faithfulness, helpfulness, groundedness. Often paired with a `comment` rationale and (on the related EVALUATOR span) `model`/`provider`/`temperature` in raw attributes.
- **BOOLEAN** — `value` is 0 or 1. A pass/fail **code** evaluation (unit test, regex/JSON schema match). No LLM meta, often no `comment`.
- **CATEGORICAL** — `string_value` is a label from a fixed set (e.g. `safe`/`unsafe`, `A`/`B`/`C`).
- **TEXT** — `string_value` is free-form (e.g. a generated critique, a suggested rewrite).

> Note: ATIF ingest can auto-create an evaluator result named `harbor.verifier` from a trajectory's `extra.verifier_result`. Cleanly-named scores are posted via `POST /evaluator-results`.

## Annotation

`Annotation` (`annotations_schemas.Annotation`) is a **post-hoc human/process** signal, distinct from `EvaluatorResult` (which is automated pipeline output). It is **kind-discriminated** — the shape changes per `kind`.

Shared (read) fields: `annotation_id`, `workspace`, `span_id` (null = session-level), `session_id`, `created_by`, `created_at`, `ingested_at`.

| Kind | Discriminator | Payload fields |
|---|---|---|
| **feedback** | `kind="feedback"` | `value`: `"positive"` \| `"negative"` (thumbs up/down). |
| **note** | `kind="note"` | `text`: free text (1–10,000 chars). |
| **label** | `kind="label"` | `value_type`: `"text"` \| `"numeric"`; `value`: string or number; `name`: what the label measures (required when numeric — e.g. `severity`, `helpfulness`). |
| **metadata** | `kind="metadata"` | `metadata`: arbitrary `dict[str,Any]` (≥1 entry). |

A view must handle both **span-level** (`span_id` set) and **session-level** (`span_id` null) annotations, and all four kinds.
